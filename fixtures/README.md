# GSI fixtures

## Please capture real matches

Most of what CS2Live knows about CS2's Game State Integration feed started as a hypothesis built
from Valve's old CS:GO documentation. Real captures settle it; one Wingman match has so far (see
`real/` below). Still wanted:

1. **A full Competitive or Premier match you play** (warmup to scoreboard), ideally one that goes
   to overtime.
2. **Ideally some spectating**: watch a friend's match in-game, or a GOTV/demo, for a few
   rounds. That shows which observer-only sections (`allplayers_*`, `bomb`, `grenades`,
   `phase_countdowns`) CS2 actually sends.
3. Anything odd you hit: a reconnect, a halftime, overtime, a tactical timeout, a surrender
   vote.

How:

```sh
# in .env
GSI_CAPTURE=1

yarn live          # or yarn dev
# play; every payload is appended to captures/gsi-<time>.ndjson
```

Captures land in `captures/` (gitignored). They contain your Steam ID, name, clan tag and the
Steam IDs and names of players you spectate (the GSI token is stripped). Send them to Claude or drop them
in `fixtures/real/` **after anonymising** (see the `gsi-replay` skill). The first line of each
capture also records the HTTP headers CS2 sent, which tells us whether CS2 sends a
`Content-Type` header (see `scripts/live.ts`).

## Real captures (`real/`)

Anonymised with `yarn gsi:anonymise` (Steam IDs from `fakeSteamId(100)`, names `Player 1…n`, clan
tags blanked). The recorder is `fakeSteamId(100)`. Never edit them by hand.

| File                     | Scenario                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------------------------------- |
| `wingman-inferno.ndjson` | Wingman on Inferno, menu to menu, lost 5:9 from T. Dies early in most rounds; ends without an `over` |

## Synthetic fixtures (`synthetic/`)

Generated by `yarn gsi:fixtures` from the simulator in `src/lib/server/gsi/sim/simulate.ts`.
They follow our hypothesis of the feed and drive the tracker tests. Regenerate them after
changing the simulator; never edit them by hand.

| File                          | Scenario                                                 |
| ----------------------------- | -------------------------------------------------------- |
| `full-match.ndjson`           | Warmup, then a full competitive match to gameover        |
| `mid-match-join.ndjson`       | Joins at round 8 (no warmup, scores already set)         |
| `quit-before-gameover.ndjson` | 9 rounds, then the main menu, never comes back           |
| `death-spectate.ndjson`       | Dies every round and spectates a teammate                |
| `overtime.ndjson`             | 12-12 after regulation, decided in overtime              |
| `reconnect.ndjson`            | Disconnects after round 6 for 5 minutes, then comes back |
| `wingman.ndjson`              | A Wingman match (8-round halves)                         |

The simulator's Steam IDs sit at the very top of the account-ID range (`7656120225516...`), far
above any real account, so seed data can never collide with a real player.

## Format

NDJSON, one JSON value per line:

```
{"meta":{"startedAt":"…","appVersion":"…","headers":{"content-type":"application/json"}}}
{"t":1793556000000,"p":{"provider":{…},"map":{…},"round":{…},"player":{…}}}
```

`t` is when the payload was received (epoch ms), `p` the payload without its `auth` block.

## Replaying

```sh
yarn gsi:replay fixtures/synthetic/full-match.ndjson --speed 20 --as <your SteamID64>
```

`--as` makes a fixture look like it came from your account, so the tracker records it.
